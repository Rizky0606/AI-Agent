# Capability Acceptance Report

Date: 2026-10-13

## Implemented

- Worker and scheduler standalone entrypoints remain alive, handle SIGTERM/SIGINT, close durable clients, recover interrupted tasks.
- Production worker now constructs one guarded `ToolRegistry`; API constructs the catalog registry with the same built-in registration policy.
- Explicit generic `payload.toolName` tasks execute through `ToolRegistry.executeTool`, persist `task.tool_call`, checkpoint output, and complete. Approval-required tool calls persist a waiting checkpoint, resume the same task, and revalidate/consume approval before execution; verified by regression test, not production smoke.
- Generic natural-language tasks (`kind` starting with `generic`, no `toolName`, no `useRuntime`) now execute through the real path: `IntentAnalyzer` → `Planner` → `ModelGateway.chat` (model from `payload.model`, else `DEFAULT_CHAT_MODEL`), guarded by `PermissionEngine` under `model:chat`. Step-4 evaluator evidence is derived from the actual model output, tool result, or checkpoint state — the fabricated `matchCount: 3` / `result: 'ok'` / `'Task berhasil diselesaikan…'` evidence is gone for non-simulated tasks. `isSimulation: true` retains placeholder behaviour.
- Generic tasks fail closed: no `ModelGateway` or no resolvable model → task `failed` with `requires a ModelGateway` / `requires payload.model or DEFAULT_CHAT_MODEL`; no synthetic completion.
- Generic orchestration contract (`kind` starting with `generic`, no `toolName`, no `useRuntime`): `payload.prompt` / `payload.instructions` / `payload.goal` supplies the instruction (falling back to `task.kind`); `payload.model` selects the model (else `DEFAULT_CHAT_MODEL`); `payload.workspaceId` scopes the run (defaults to the task id); `payload.acceptanceCriteria` overrides the default single `task_output` artifact criterion. Every field is optional. `payload.mode` (`auto|fast|coding|complex|research`) is forwarded to the router but only `coding` has an observable effect: it sets `task.started.selectedRuntimeId` to the preferred runtime (observed `omp`). The persisted `task.started.intent` and `runtime` come from `IntentAnalyzer` on the prompt, not from `mode` — observed with `mode: 'research'`, which still reported `intent: 'simple_chat'` / `runtime: 'fast_model'`.
- `task.completed` now carries the real `evaluationResult` for the generic path; `task.tool_call.input` records the actual prompt instead of a hardcoded query.
- Resuming a task whose checkpoint is `stepIndex: 2` / `lastExecutedAction: waiting_approval` / `actionState.approved: true` replays the guarded step-2 action with the approval id, so the approved capability executes exactly once rather than being skipped.
- Production registry intentionally exposes only `web_fetch` until workspace/browser/artifact runtime dependencies receive explicit production wiring.
- `/v1/catalog` now includes registered `ToolRegistry` metadata when a registry is injected, alongside skills.
- Android attachment UI no longer creates `https://placeholder.local/image.png`; explicit unavailable state rendered. No upload contract exists.
- Capability matrix: `docs/capability-matrix.yaml`.

The high-risk approval flow is production-smoked end-to-end from the packaged Windows app (approve and deny paths above).
- MCP now has a real transport, so `McpHub` is no longer unreachable. `StdioMcpServerAdapter` (`packages/mcp/src/transport/stdio-adapter.ts`) speaks newline-delimited JSON-RPC over a child process: lazy spawn, `initialize` handshake with a separate longer budget, per-request timeout, `AbortSignal` cancellation that also emits `notifications/cancelled`, child death failing every in-flight request, and server-initiated requests answered with `-32601` so a server never blocks on a reply. Non-text content parts are marked `[<type> content omitted]` rather than dropped, and anything the child writes to stderr or to stdout that is not JSON is surfaced as a diagnostic instead of being swallowed. The worker launches servers named by `MCP_SERVERS` and registers their allowlisted tools into the same registry that serves `browser_navigate`; one server failing to launch is logged and skipped so it cannot take the worker down.
- MCP calls are gated by policy, not just by the allowlist. `McpHub` names actions `tool:mcp_<serverId>_<toolName>`, which matched no rule in `DEFAULT_ACTION_RULES`, so deny-by-default would have refused every MCP call while still listing the tools as available. `packages/permissions/src/engine.ts` now classifies `tool:mcp_*` as MEDIUM, and because the scope is `external_mcp` (not `workspace`/`sandbox`) the engine escalates to `require_approval`. Verified by `packages/permissions/test/permissions.test.ts` and by an integration test that asserts an unapproved MCP call throws `ApprovalRequiredError` before the child process runs, and that an approved call returns content wrapped in `<untrusted_content is_instruction="false">`.
- `MCP_SERVERS` grants arbitrary local process execution to whoever can set it, so it is documented in `.env.example` as a deployment-time control that must never be driven by end-user input. Parsing is strict: a malformed entry throws with the offending field named, because silently registering nothing would be indistinguishable from a server that exposes no tools.
- Multi-step planning for generic tasks still executes as one bounded model step; planner output is recorded as evidence, not dispatched step-by-step.
- Android attachment upload remains unavailable by design until an authenticated artifact-upload contract exists.
